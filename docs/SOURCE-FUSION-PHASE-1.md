# Source Fusion Phase 1

Status: implemented on the generic Engine path.

## Goal

Source Fusion is the project-neutral intake layer between uploaded customer files
and Rekixo authoring state. It must reduce repetitive setup without inventing
architectural facts.

The normal operator workflow is:

1. Create a project.
2. Drop the complete source pack.
3. Analyze sources.
4. Prepare a web GLB when the authoring model is FBX.
5. Build/review the draft.
6. Continue into visual authoring and publication.

No customer/project SHA-256 profile is required for Source Fusion.

## Supported Phase 1 sources

| Format | Phase 1 state | Rekixo use |
| --- | --- | --- |
| GLB | ready | web/authoring geometry candidate |
| FBX | partial | geometry/material/floor analysis plus one-click GLB derivative |
| ASCII DXF | partial | named architectural layer hints |
| DWG | controlled processor required | preserved evidence until CAD conversion |
| SKP / SKB | controlled processor required | preserved evidence until SketchUp processing |
| PDF | evidence | page rasterization and calibrated plan alignment |
| JPG/PNG/WebP/TIFF | evidence | visual/material reference |
| CSV/TSV | ready | measured room queue |
| DRS/JSON | partial | metadata/resource-reference inspection |

A file being accepted does not mean Rekixo claims all semantics inside that format
have been decoded.

## Source-fact contract

Phase 1 produces a SourceFusionReport. Facts are bound to the source asset ID and
carry:

- key;
- value;
- confidence;
- basis;
- observed versus suggested status.

Examples include parsed model mesh/material counts, inferred floor elevations,
ASCII-DXF layer hints, room-sheet row counts and literal DRS/JSON resource
references.

Future CAD/SketchUp processors must add facts through the same provenance model
rather than hardcoding a project profile.

## FBX web derivative

Studio can prepare a binary GLB directly from the selected FBX authoring model.

Safety rules:

- the original FBX asset is never mutated;
- the source asset remains the authoring model;
- the generated GLB is stored as scene.publishModelId;
- source material names and basic PBR-compatible material values are retained;
- unresolved external texture maps are stripped instead of silently embedding a
  fake visual result;
- generated GLB must remain within the same 64 MB Studio asset boundary;
- generated bytes are SHA-256 addressed before persistence/publication.

This browser conversion is an operator-friendly first processor. The Source
Fusion contract intentionally allows the implementation to move to an isolated
queued processor later without changing the project model or UI contract.

## Authority / precedence

Phase 1 does not combine conflicting values automatically. The intended
precedence for later reconstruction is capability-specific:

- supplied 3D model: geometry and visible source mesh identity;
- CAD/drawing: dimensions, plan topology and opening evidence after controlled
  decoding;
- SketchUp source: component/material/supporting geometry evidence after
  controlled decoding;
- PDF: dimension/plan/reference evidence;
- rendered image: visual-style evidence only;
- DRS/metadata: resource/material linkage evidence;
- CSV/TSV: explicit structured room measurements.

Conflicts stay visible for review.

## Phase 2 input contract

Automatic Building Draft must consume Source Fusion facts rather than reading
customer names or hashes. Phase 2 will add:

- controlled DWG architectural extraction;
- controlled SKP/SKB component/material extraction;
- cross-source coordinate/scale alignment;
- wall graph construction;
- room derivation;
- door/window placement;
- repeated-floor fingerprint detection;
- review queue for source conflicts.

## Phase 3 input contract

The simplified visual editor will operate on the reviewed Phase 2 scene:

- drag/drop wall and opening correction;
- touch/mouse room reshape;
- repeated-floor exceptions;
- furniture drag/drop;
- material presets;
- real wall gaps for reviewed openings;
- publish-oriented final review.

Advanced numeric controls remain fallback tools, not the primary workflow.
